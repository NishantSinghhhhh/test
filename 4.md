# Future Proposal
## Ianvs Example Restoration & README Standardization

## 1. Background

The Ianvs benchmark repository currently contains a wide variety of example benchmarks and learning scenarios. However, upon thorough review, it has been identified that many of these examples are not running properly in their current state. Additionally, a significant number of them do not have updated or accurate README files, making it difficult for contributors and evaluators to understand, reproduce, or build upon these examples.

The following examples have been identified as requiring restoration and updated documentation:

- governet_single_bench (objective.md, subjective.md)
- imagenet/automatic
- imagenet/manual
- llm-edge-benchmarking-suite/single_task_bench
- llm-edge-benchmarking-suite/single_task_bench_with_compression
- pcb-aoi/incremental_learning.md
- aoa_single_bench_Tforest.md
- cityScapes_lifelong_learning.md
- cityScapes_singletask_learning_bench.md
- LLM_Agent_Benchmark_single_task_learning.md
- llm_simple_qa.md

## 2. Objective

The primary objective of this proposal is to restore and standardize all of the above-listed examples. This involves two key actions:

- **Updating the READMEs:** Each example will receive a fully updated, accurate, and standardized README file that clearly describes the purpose, setup, dependencies, and execution steps for that benchmark.
- **Updating the Code:** The underlying code for each example will be reviewed, debugged, and updated to ensure it runs successfully in the current Ianvs environment. Any deprecated dependencies, broken paths, or outdated configurations will be corrected.

# 3. Implementation Plan

**How will I be doing it:**

All of the listed examples have already been run and tested locally. The issues present in each have been identified and documented. The implementation will now proceed as follows:

**Step 1 — Pull Requests**
For each example, a dedicated pull request will be raised one by one to address the identified issues. Each PR will be focused, clearly described, and linked to the relevant example so reviewers can track progress systematically.

**Step 2 — Environment Setup**
For every example, a fresh Conda environment will be created to ensure a clean, isolated, and reproducible setup. The README will include the exact commands to create and activate the environment, along with all required dependencies and their verified versions.

```bash
conda create -n -env python=
conda activate -env
pip install -r requirements.txt
```

**Step 3 — Dataset Download**
Clear, copy-paste-ready commands will be provided for downloading the required dataset(s) for each example. This includes the download source (e.g., wget, git-lfs, Hugging Face, or cloud storage), the correct target directory to place the data, and any extraction or preprocessing steps needed before running the example.

**Step 4 — Additional Repository Dependencies**
If an example depends on an external GitHub repository (e.g., Sedna or any algorithm library), the README will include explicit instructions for cloning and setting up those repositories, along with any version pinning or build steps required.

**Step 5 — Model Download**
Where a pre-trained model is required, step-by-step instructions will be provided to download it from the appropriate source, place it in the correct directory, and verify that it is correctly loaded by the example before execution.

**Step 6 — Running the Example**
Once the environment, dataset, and models are in place, the README will provide the exact command(s) to run the benchmarking job end-to-end, along with the expected output so users can confirm a successful run.

**Step 7 — Troubleshooting**
A dedicated troubleshooting section will be added to each README covering the most common failure points identified during local testing. This includes dependency version conflicts and how to resolve them, CUDA/CPU device compatibility issues and how to fall back gracefully, broken or misplaced file paths and how to correct them, missing environment variables and where to set them, and any example-specific known issues with their corresponding fixes.
