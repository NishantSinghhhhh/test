## Fix Multiple Execution Failures in Cityscapes-Synthia Lifelong Learning Example - Curb Detection

**Note: This section addresses bugs specific to the curb detection task only.**

## 1. Background

### Selected Example
The **Cityscapes-Synthia Lifelong Learning** example (`examples/cityscapes-synthia/lifelong_learning_bench/curb-detection`) benchmarks a road-curb detection model which comes under the lifelong learning paradigm. We have already heard about the RFNET model and it used in various other examples in ianvs. It uses the **RFNet** backbone and relies heavily on **Sedna** to start an edge-cloud architecture where a model continuously learns from two task domains: `real` (Cityscapes) and `sim` (SYNTHIA). Sedna provides the core lifelong learning modules used by this example, including `SeenTaskLearning`, `TaskAllocation`, `TaskRemodeling`, and cloud knowledge management.


### Problem Description

Through attempting to complete this example end to end, there was a continual cascade of 12 individual bugs across the example level code within Sedna and the Sedna core library (Ianvs's own backend algorithm) which inhibited the evaluation phase from executing; from API inconsistencies and diverse types, to improper model persistence and numpy shape violations were all part of the failures.

The above mentioned bugs were all identified, debugged, and verified locally. The solutions for all have been verified locally and are now ready for main repository application.

### Bug 1 — `AttributeError`: `TaskAllocationByOrigin` has no `.get()`

**Location:** `seen_task_learning.py` line 186

**Cause:** The code we have it treats `self.seen_task_allocation` as a `dict` but it is an object instance. To solve this the framework was partially changed from config-dict style to OOP style but not all call sites were updated.

**Log:**
```
AttributeError: 'TaskAllocationByOrigin' object has no attribute 'get'
  File ".../seen_task_learning.py", line 186
    method_name = self.seen_task_allocation.get("method")
```

**Fix:**
```python
if isinstance(self.seen_task_allocation, dict):
    method_name = self.seen_task_allocation.get("method")
else:
    method_name = getattr(self.seen_task_allocation, 'method', None) or \
                  self.seen_task_allocation.__class__.__name__
```

### Impact Assessment

These bugs affect **three distinct layers** of the stack:

- **Example-level** (`rfnet/`, `cityscapes.py`, `task_allocation_by_origin.py`) — Bugs 3, 4, 5, 7, 12 are isolated to this example and can be fixed without touching any core code.
- **Sedna core** (`seen_task_learning.py`, `task_remodeling.py`, `cloud_knowledge_management.py`, `datasources/__init__.py`) — Bugs 1, 2, 8, 10, 11 are in **Sedna — Ianvs's own built-in algorithm library** located at `core/lib/sedna/`. These bugs affect **any lifelong learning example** that invokes the same Sedna modules, not just Cityscapes-Synthia.
- **Ianvs paradigm core** (`lifelong_learning.py`) — Bugs 9, 13 are in the core paradigm controller (`core/testcasecontroller/algorithm/paradigm/lifelong_learning/`) and affect all lifelong learning benchmarks across the entire Ianvs framework.

The combined effect is that **the lifelong learning paradigm is entirely non-functional** for this example, and likely broken for any other example that follows the same execution path.

# Fix Multiple Execution Failures in Cityscapes-Synthia Lifelong Learning Example - Semantic Segmentation

**Note: This section addresses bugs specific to the semantic segmentation task only.**

## 1. Background

### Selected Example
The **Cityscapes-Synthia Lifelong Learning** example (`examples/cityscapes-synthia/lifelong_learning_bench/semantic-segmentation`) benchmarks a semantic segmentation model under a lifelong learning paradigm. It uses the **RFNet** backbone and relies heavily on **Sedna** — Ianvs's own built-in algorithm library — to simulate an edge-cloud architecture where a model continuously learns from two task domains: `real` (Cityscapes) and `sim` (SYNTHIA). Sedna provides the core lifelong learning modules used by this example, including `SeenTaskLearning`, `TaskDefinition`, `UnseenTaskProcessing`, and `TaskRemodeling`.

### Problem Description

Attempting to execute this example end-to-end results in **a cascading chain of 15 distinct bugs** spanning both the example-level code and the **Sedna core library** (Ianvs's own algorithm backend). These bugs completely prevent the evaluation phase from running. The failures range from uninitialized estimators and type mismatches to array indexing errors and missing import configurations.

All bugs were discovered and debugged locally. The fixes have already been validated on a local setup and are ready to be applied to the main repository.

**Location:** `metrics.py` line 142

**Cause:** The script bypassed unseen task inferences by supplying an empty list `[]`. When NumPy evaluated this, it created a 0-dimensional array, causing the attempt to retrieve index `0` to fail.

if np.ndim(pre_image) == 0 or np.size(pre_image) == 0:

### Bug 14 — `IndexError`: too many indices for array in `task_remodeling.py` 🔴 Critical

**Location:** `task_remodeling.py` line 68

**Cause:** Test datasets often do not have loaded ground truth labels `samples.y`, resulting in an empty array object. Trying to slice it `[_inx]` throws an IndexError since there are no dimensions to slice.

try:
    task_df.y = np.array(samples.y)[_inx]

    task_df.y = None

### Impact Assessment

These bugs affect **three distinct layers** of the stack:

- **Example-level** (`cityscapes.py`, `accuracy.py`, `metrics.py`, `basemodel.py`) — Bugs 2, 4, 7, 11, 12, 13 are isolated to this example and can be fixed without touching any core code.
- **Sedna core** (`seen_task_learning.py`, `task_definition.py`, `unseen_task_processing.py`, `task_remodeling.py`) — Bugs 1, 6, 8, 9, 14, 15 are in **Sedna — Ianvs's own built-in algorithm library** located at `core/lib/sedna/`. These bugs affect **any lifelong learning example** that invokes the same Sedna modules.
- **Ianvs core** (`lifelong_learning.py`, `dataset.py`) — Bugs 3, 5, 10 are in the core controllers and affect all lifelong learning benchmarks across the entire Ianvs framework.

The combined effect is that **the lifelong learning paradigm is entirely non-functional** for this example, and likely broken for any other example that follows the same execution path.

5. **Patch Sedna's core modules** directly within the Ianvs repository, since Sedna is Ianvs's own library and not an external dependency.
